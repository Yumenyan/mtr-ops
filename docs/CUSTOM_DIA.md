# カスタムダイヤ(時刻表運転)

MTR の路線・車庫・ホーム・レール(線路のハードウェア側)はそのまま使い、その上に「時刻表どおりに走らせる」仕組みを足します。
MTR の jar も、MTR に保存されているデータ(路線・車庫の出庫設定など)も一切書き換えません。通常の鉄道ダッシュボードの動作も変わりません。

## 使い方(すべてゲーム内)

1. **ダイヤ式鉄道ダッシュボード**を手に持って使う(右クリック)。
   - 入手: クラフト(MTRの鉄道ダッシュボード + 時計)、またはクリエイティブの「移動手段」タブ。`/mtrops dia` でも開けます。
   - 左に一覧、右に MTR と同じ地図(表示・移動・拡大だけ。クリックしても何も編集しません)。
2. **路線タブ**: MTR の鉄道ダッシュボードで作った路線を選び「ダイヤ管理へ移行」。
   - 移行すると、その路線を含む車庫に時刻表が無ければ、MTR の車庫の出庫設定(実時刻の出庫リスト / 1時間あたりの本数)から初電・終電・間隔の初期値を作ります。
   - 保安装置(なし/ATS/ATC)、回復運転(+km/h・上限km/h・何秒遅れから)もここで設定。「通常(MTR)に戻す」で元の運転へ。
3. **車庫・時刻表タブ**: 車庫を選び「時刻表を編集…」。
   - 基本・時間帯: 基準駅・初電・終電・出庫の余裕・ずらし・自動の噛み合わせ、時間帯ごとの運転間隔
   - 増便・取りやめ: 基準駅の発車時刻をカンマ区切りで(24時以降は 24:30 のように)
   - 停車延長: 停車駅ごとの停車時間の延長(待避・調整)
   - 時刻表を確認: 便ごとの出庫・基準駅の発車・終着
4. **全体タブ**: 同じホームの最小間隔・遅れ時のドア最短・待避の上限・余裕時分。
5. 左下の「保存」でサーバーへ送られます(権限: MTRと同じ。`requireOpToEdit` でOPのみにできます)。

## 出庫時刻の仕組み(MTRのデータを書き換えない)

MTR の車庫は、保存された出庫設定から作業用の出庫時刻(`Depot.tempDepartures`、保存されない)を作って列車を出します。
mtrops はその作業用の出庫時刻だけを、カスタムダイヤの車庫について時刻表の出庫時刻に置き換えます(`DepotMixin`)。
保存された設定はそのままなので、通常の鉄道ダッシュボードで見える内容は変わらず、ダイヤ管理を解除すれば MTR の設定どおりの出庫に戻ります。

## 列車の動き(カスタムダイヤの列車だけ)

| 機能 | 内容 |
|---|---|
| 発車時刻 | 早く着いたらドアを開けたまま発車時刻まで待ちます。遅れているときは、ドアが一定時間(既定3秒)開いたらすぐ閉めて発車します。 |
| 出庫 | 時刻表の出庫時刻に MTR が出庫させます。出庫した列車には、その時刻に一番近い便が割り当てられます。 |
| ATC | 前方の閉塞に先行列車がいると、その手前で止まれる速度に連続で制限します。 |
| ATS | ATC と同じ判定で、速度を段階に丸めます。 |
| 回復運転 | 遅れが設定秒数以上のとき、レールの最高速度 + 指定 km/h(上限まで)で走れます。 |

時刻はサーバーの時計(既定はサーバーのタイムゾーン。`config/mtrops.json` の `timeZone` で変更可。例 `"Asia/Tokyo"`)です。

## Web・APIでの扱い
- `/api/dia` で設定・時刻表・運行中の列車の便と遅れを読めます(読み取りのみ。Webの編集画面は廃止)。
- 到着予想(`etas`)は時刻表の到着(`scheduled`)と、早着時の待ち合わせを反映した見込み(`time`)を出します。
- 駅の時刻表(`/api/schedule/駅`)は、カスタムダイヤの車庫を時刻表どおりに出します。
- Webアプリでは路線に「ダイヤ」の印が付き、列車詳細で「定刻 ▶ 見込」を表示します。

## できないこと(MTR の仕様)
- 列車ごとに入るホームを変えることはできません(ホームの並びは「路線+車庫」で経路生成時に決まります)。

## 技術メモ
- 差し込み先: `Train.simulateTrain`(速度・停車時間)、`TrainServer.simulateTrain`(同期)、`Depot.generateTempDepartures`(出庫時刻)。
- 差し込みが効かない場合はゲームを止めず、ログにエラーを出してカスタムダイヤの列車制御だけ無効になります。
