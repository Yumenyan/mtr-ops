# カスタムダイヤ(時刻表運転)

MTR の路線・車庫・ホームはそのまま使い、その上に「時刻表どおりに走らせる」仕組みを足します。
MTR の jar は変更しません。通常方式の路線は MTR の動きのままです。

## 使い方

1. **路線ごとのダイヤ方式**を決める
   - ゲーム内: `H` キー(または `/mtrops dia`)
   - Web: `L` キーで開くアプリの「ダイヤ」タブ → 路線のダイヤ方式
   - 「カスタムダイヤ」にした路線を含む車庫の列車が時刻表運転になります。
2. **車庫ごとの時刻表**を組む(Web の「車庫ごとの時刻表」)
   - 基準駅・初電・終電・時間帯ごとの運転間隔(朝ラッシュ/日中/夕ラッシュなど)を入れて保存します。
   - 車庫を出る時刻は自動で逆算されます(MTR の走行時間計算と同じ計算)。
   - 「他の車庫の列車と噛み合うよう、ずらしを自動で決める」が有効なら、同じホームを使う列車どうしが重ならないよう全便をずらします。
   - 同じホームで詰まる便は、手前の停車駅で自動的に待たせます(待避・抑止)。別のホームがある駅では追い越し(待避)、同じホームしかない区間では追い越しません。
   - 臨時便・運休、駅ごとの停車延長も入れられます。
3. 保存すると、サーバーで時刻表が作られ、車庫の出庫時刻(MTR の「実時刻で出庫」設定)が自動で書き換わります。
   カスタムダイヤを解除すると、車庫の出庫設定は元に戻ります。

## 列車の動き(カスタムダイヤの列車だけ)

| 機能 | 内容 |
|---|---|
| 発車時刻 | 早く着いたらドアを開けたまま発車時刻まで待ちます。遅れているときは、ドアが一定時間(既定3秒)開いたらすぐ閉めて発車します。 |
| 出庫 | 時刻表の出庫時刻に MTR が出庫させます。出庫した列車には、その時刻に一番近い便が割り当てられます。 |
| ATC | 前方の閉塞に先行列車がいると、その手前で止まれる速度に連続で制限します(MTR 標準は制限速度まで加速して直前で止まる)。 |
| ATS | ATC と同じ判定で、速度を 15/25/45/65/85 km/h の段階に丸めます。 |
| 回復運転 | 遅れが設定秒数以上のとき、レールの最高速度 + 指定 km/h(上限 km/h まで)で走れます。 |

時刻はサーバーの時計(既定はサーバーのタイムゾーン。`config/mtrops.json` の `timeZone` で変更可。例 `"Asia/Tokyo"`)です。

## できないこと(MTR の仕様)

- 列車ごとに入るホームを変えることはできません。ホームの並びは「路線+車庫」で経路生成時に決まります。
  待避する系統は、待避ホームを通る別の路線・車庫として作ってください。
- MTR の車庫画面で、カスタムダイヤ中の車庫の出庫時刻を変えても、mtrops が時刻表の値に戻します。

## 技術メモ

- 差し込み先: `mtr.data.Train.simulateTrain`(速度=getRailSpeed の置き換え、最後に停車時間の調整)、
  `mtr.data.TrainServer.simulateTrain`(停車・速度を変えた列車を0.5秒ごとにクライアントへ同期)。
- 差し込みが効かない場合(MTR の版が違うなど)はゲームを止めず、ログにエラーを出してカスタムダイヤの列車制御だけ無効になります。
- 時刻表はサーバーとクライアントが同じ計算(DiaPlanner)で作るため、送るのは設定と理想走行だけです。
- 開発環境で、MTR 3.2.2-hotfix-1 入りの専用サーバーを起動し、レール・ホーム・車庫・路線をプログラムで作って動作を確かめました
  (出庫が時刻表どおり / 早着時に発車時刻ちょうどに発車 / ATC・回復運転)。
